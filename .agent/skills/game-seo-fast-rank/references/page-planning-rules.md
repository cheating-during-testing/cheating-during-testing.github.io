# 页面规划规则

## 首页

主词优先：游戏实体名本身，如 `steal an egg`。

首页目标：

- 清晰回答“这是什么游戏/这个站能帮我找什么”
- 承接品牌/游戏主词
- 给所有 P0/P1 子页明确内链

## 子页

每个子页必须绑定一个 `intent cluster`，不是绑定一个孤立关键词。

同一意图簇内：

- 合并同义/近义关键词（如 `best pets` 与 `pet tier list`）
- 用 Primary 选择算法挑主词：最近月搜索量 → Rising 强度 → 自然完整游戏名表述
- 其余词进入 secondary / mergedKeywords

页面规划优先：

1. 搜索量（最近可用月）
2. 上涨趋势/近期 Rising signal
3. 与游戏主词相关度
4. 页面是否能独立提供价值
5. Fact Pack / 内容支撑
6. SERP 机会（若无数据则为 0）

MVP1 暂不做复杂 KD。

## 页面数量

页面数量由**独立意图**动态决定，不是固定配额：

- 有多少经搜索证据（及爆发模式下经确认的核心机制）证实的独立玩家需求，就建多少页
- 同义意图必须合并，禁止为了凑页数拆页
- **不要**把「首页 + 2~5 子页」当作目标或上限

不设置总页面数上限。所有通过搜索证据、事实证据和独立意图判断的页面都进入规划；页数只由有效机会决定。

## 选页与推迟

- 首页永远入选
- 成熟需求（established）：搜索量为 0 且无 Rising → 推迟，不建页
- 爆发新词（breakout）：月搜索量可为 null，但需要强 Rising/Autocomplete，或 Fact Pack 确认的核心机制 + 证据备注
- 禁止仅凭游戏机制、在毫无搜索证据时发明页面（爆发模式下有确认实体与证据备注的除外）

## URL

- 小写
- 短
- 用连字符
- 尽量包含需求核心词
- 层级只有在语义自然时使用，例如 `/eggs/rare-eggs/`

## 防 Cannibalization

如果两个页面的主要用户问题基本相同，则合并。

例：

- `best pets`
- `pet tier list`

如果 SERP/意图实际相同，优先一个 `/pets/` 页面覆盖，不机械拆两页。
